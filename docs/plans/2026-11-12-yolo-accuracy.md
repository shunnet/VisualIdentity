# YOLO 识别精度：推理缩图与训练对齐、训练推荐值（2026-11-12）

## 反馈与结论

用户问：YOLO 的识别精度能不能像 Anomalib 那样优化——给出推荐值，让训练后的模型识别精度提到最高。

| 问题 | 根因 | 处理 | 实测 |
|---|---|---|---|
| 识别时缩图方式与训练不一致 | 应用的 C# 推理把原图缩到模型输入尺寸时用 SkiaSharp 的**最近邻**（`ImageConfig.DefaultSamplingOptions`），而 `YoloOptions.SamplingOptions` 的注释写的是“默认 Linear”；Ultralytics 训练与预测用的是 `cv2.INTER_LINEAR`（双线性、不抗锯齿） | 默认改为 Linear / 无 mipmap，并用测试守住（数值与双线性一致、默认值） | 同一个模型、3024×3024 的真实照片缩到 640：mAP50-95 0.556 → **0.583**，mAP50 0.849 → **0.900**，召回率 0.743 → **0.797**；1024 px 的数据集上 mAP50-95 0.395 → **0.427** |
| 训练的输入尺寸、模型、轮数、验证集全靠用户猜；默认 500 轮在这份数据上过拟合 | 没有依据。完整训练 300 轮（不早停）最后 10 轮的 mAP50-95 均值只有 0.4165（mAP50 0.5325），低于 100 轮的 0.4364 / 0.5914 | 训练弹窗按数据集给出推荐值（输入尺寸、模型规格、轮数、是否用验证集）与依据，一键套用；第一次打开自动套用 | 见第 2、3 节 |
| 查过、结论是不用改的 | letterbox 补边颜色、小图不放大、默认置信度、Ultralytics 默认早停 | — | 见第 4 节 |

## 1. 推理缩图与训练不一致

Ultralytics 在训练（有增强）与预测时缩小图片用 `cv2.INTER_LINEAR`——双线性、按目标像素点采样、不做抗锯齿。应用的 C# 推理路径缩图用的是最近邻：
缩小倍数越大，最近邻和双线性的输入差得越多（4.7 倍时每个目标像素只取一个源像素，而不是周围四个的加权）。

测法：用应用**自己**的 C# 推理路径（`Snet.Yolo.Server` 的 `Yolo` + ONNX Runtime）识别一批图，再用 Ultralytics 自己的匹配与 AP 计算评估（conf 0.001、IoU 0.7），所以只有“缩图方式”不同。

| 数据 | 采样方式 | mAP50-95 | mAP50 | 召回 |
|---|---|---|---|---|
| 120 张 3024×3024 真实照片（缩到 640，4.7 倍；本机 GTX 1060 上用 600 张同类原图训练的 YOLO26n） | 最近邻（旧默认） | 0.5555 | 0.8493 | 0.7435 |
| | **双线性（新默认）** | **0.5827** | **0.9000** | **0.7969** |
| | 双线性 + mipmap（抗锯齿） | 0.5651 | 0.859 | 0.7663 |
| 414 张留出图（长边 ≤1024，混合长宽比；服务器上训练的 YOLO26n，640） | 最近邻 | 0.3952 | 0.5525 | 0.576 |
| | **双线性** | **0.4270** | **0.5796** | **0.5916** |
| | 双线性 + mipmap | 0.4227 | 0.5734 | 0.591 |

* 抗锯齿（mipmap / INTER_AREA / Lanczos）也不行：它比训练时的输入更“平滑”，同样掉点（Python 侧同一批权重：双线性 0.5933、最近邻 0.5721、INTER_AREA 0.5649、PIL 抗锯齿 0.5600、Lanczos 0.5666）。顺带：Ultralytics 自己验证时对缩小的图用的是 INTER_AREA 而不是训练时的 INTER_LINEAR，所以它报出的 mAP 在这种大幅缩小的图上比应用现在的路径还低。
* 已训练好的模型**不用重训**，部署新版即可受益；其他任务（分割、姿态、旋转框、分类）共用同一个默认值，一并受益。
* 实现：`ImageConfig.DefaultSamplingOptions` 改为 `new(SKFilterMode.Linear, SKMipmapMode.None)`；`YoloInputResizeTests` 检查默认值、并把 256→64 的缩小结果与“周围 2×2 像素的平均”逐像素对比（改回最近邻时两项测试都会失败，已做过破坏性验证）。

## 2. 对比实验（服务器 RTX 4080，临时目录，生产部署未动）

数据：用户开发实例里的一个检测工程（2762 张图、8842 个矩形框、4 类），按“md5(工程 id + 文件名)”固定划分：15% 做验证（414 张），其余 2348 张训练；
为了在 2 MB/s 的链路上传输，长边超过 1024 的图缩到 1024（JPEG 质量 92，框是归一化坐标不受影响）。固定 seed=0、`cache=ram`、AMP、批大小 32（m 用 16）。
训练后用 best.pt 在同一份验证集上评估（conf 0.001，IoU 0.7）。

**怎么比才不被噪声骗**：验证集只有 414 张，逐轮的 mAP50-95 会在 ±0.02 上下跳；`best.pt` 是在这条带噪声的曲线上挑最高的一轮，系统性偏乐观（比“最后 10 轮的均值”高 0.01–0.06）。
所以下表同时给出 best.pt 的成绩和**最后 10 轮均值**（带标准差），判断差别以后者为准。

| 配置 | 轮数 | best.pt mAP50-95 / mAP50 | 最后 10 轮 mAP50-95 均值（标准差） | 最后 10 轮 mAP50 均值 | 备注 |
|---|---|---|---|---|---|
| yolo26n，416 px | 100 | 0.4042 / 0.5848 | 0.3904（0.004） | 0.5571 | 输入小了就是更差 |
| yolo26n，**640 px** | 100 | 0.4410 / 0.5950 | **0.4364**（0.005） | **0.5914** | 基线，也是最好的 |
| yolo26n，960 px | 100 | 0.4372 / 0.6052 | 0.4124（0.012） | 0.5792 | 目标很大（640 px 输入下最小的 5% 也有 41–52 px），加大输入没有收益 |
| yolo26s，640 px | 100 | 0.4469 / 0.6103（最佳轮次 35） | 0.4347（0.003） | 0.6081 | 与 n 相同 |
| yolo26m，640 px | 100 | 0.4544 / 0.6277（最佳轮次 58） | 0.4282（0.007） | 0.5861 | 更大的模型没有更好 |
| yolo26n，640 px，300 轮 | 300（默认早停停在 157） | 0.4587 / 0.6468（最佳轮次 57） | 0.4165（0.004）（跑满 300 轮） | 0.5325 | 过拟合：最后阶段比 100 轮差 0.02 / 0.06 |

观察：

* **输入尺寸**：416 → 640 稳稳提升（最后 10 轮均值 +0.046）；640 → 960 没有收益。这份数据的目标很大，所以不需要放大；目标小的数据集需要更大的输入（见下节的算法）。
* **模型规格**：2000–3000 张训练图上 n 与 s 相同、m 没有更好。数据受标注质量限制（其中一个类别 `牛逼` 的 AP 近 0，`羽毛1` 只有 0.34–0.55），更大的模型没有用武之地。
* **训练轮数**：100 轮完整训练（约 3700 次参数更新）最好；300 轮（约 11000 次，Ultralytics 自动换成 SGD）最后阶段反而更差，验证集上的最佳轮次是第 57 轮。**应用现在的默认是 500 轮**，在这份数据上会更差；打开验证集时 best.pt 能避开过拟合的后段，关闭时交付的是最后的权重。
* **验证集与 best.pt**：best.pt 在带噪声的验证曲线上挑最高点，成绩偏乐观；上表里 best.pt 比最后 10 轮均值高 0.01–0.06。

## 3. 推荐值（`YoloTrainingAdvisor`）

训练弹窗（`TrainPage.razor`）按数据集画像（`YoloDatasetProfile`：图片数、标注框数、每个框相对原图的尺寸、图片分辨率）与所选设备（CPU / 显卡显存）算出四项推荐值与依据，第一次打开弹窗时自动套用，之后“使用推荐值”一键回到推荐。没有可用标注时不显示。

| 项 | 规则 | 依据 |
|---|---|---|
| 输入尺寸 | 最小的 5% 目标在网络输入上的短边 ≥ 16 px，取 32 的倍数，**不低于 640、不高于 1280**，也不超过原图分辨率；到 1280 仍然偏小则提示“先切图再标注训练”；分类任务 224 | 416 比 640 低 0.046；640 → 960 在大目标上没有收益；小目标需要更大输入是常识，这个下限与体检里“最小边 ≥ 12 px”的提示一致 |
| 模型规格 | 图片 < 3000 → n；< 15000 → s；其余 m；CPU 训练用 n；显存 < 8 GB 最多 s；l / x 只作为用户自己的选择 | 上表：2000–3000 张训练图上 n ≈ s ≥ m。更大数据集用更大模型是常识，没有在这份数据上验证，所以门槛定得保守 |
| 训练轮数 | 按约 4000 次参数更新（名义批大小 64）折算：轮数 = 4000 ÷ ⌈图片数 ÷ 64⌉，取 100 的倍数，100–500；这份数据（2762 张）= 100 轮，300 张 = 500 轮 | 100 轮（约 3700 次）最好，300 轮（约 11000 次）更差；图片少时每轮更新次数少，需要更多轮数才够，上限 500（体检里“图片很少时 ≥ 300 轮”的提示与此一致）。没有在小数据集上做对比实验 |
| 验证集 | 已标注图片 ≥ 300 张就推荐开（自动划 10%），否则不开 | 开了才有没见过的图片上的 mAP，长训练过拟合时 best.pt 也能避开后段；少于几百张时留出 10% 既让训练图更少、验证集（几十张）的 mAP 也基本是噪声 |

注意：

* 常数来自**这一份**真实数据；常识性的部分（小目标要大输入、数据多了用大模型、小数据集多训练几轮）门槛都定得保守。
* 验证图不多时逐轮 mAP 会上下跳（±0.02 左右），best.pt 的成绩偏乐观，别当成真实精度（推荐值的说明里也写了）。

## 4. 查过、结论是不用改的

* **letterbox 补边颜色**：C# 路径补黑边，Ultralytics 补 (114,114,114) 的灰边。在 414 张留出图（40% 非正方形）上两种补边的 mAP50-95 是 0.4270 对 0.4261，没有差别，不改。
* **小图不放大**：C# 在图片的宽高都小于模型输入时不放大、直接居中。320×320 的图喂 640 的模型：C# 0.5481 / 0.8707，Ultralytics 式放大 0.5271 / 0.8323，不放大反而更好，不改。
* **默认置信度**：验证页默认 0.2。100 轮的 n 与 s 最佳 F1 的置信度在 0.20–0.23，默认值就是最佳（F1 0.600 对 0.601、0.616 对 0.618）；m、960 px 与更长训练的模型在 0.35–0.41，默认 0.2 下的 F1 比最佳低 0.03–0.05（例如 m：0.554 对 0.604），这类模型在验证页把置信度调到 0.35–0.4 更合适。推荐值给出的是 n，所以默认值不改。
* **Ultralytics 默认早停（patience=100）**：开了验证集时，300 轮的训练在第 157 轮停下（最佳轮次 57）；跑满 300 轮后 best.pt 仍是第 57 轮，交付的模型相同，只是省了一半时间。曾打算加 `patience=轮数` 让学习率退火走完，实测没有收益（完整 300 轮的最后阶段反而更差），没有改。
* **ONNX 导出**：`opset 18`、与训练同尺寸，C# 路径与 Ultralytics 的结果在 3024×3024 的图上相差 0.001（0.900 对 0.901），后处理没有问题。

## 5. 没有解决 / 不确定的地方

* 分类任务：Ultralytics 的分类验证是“按短边缩放 + 中心裁剪”，应用识别时按 letterbox 补边；非正方形图片上两者的视野不同，本次没有实测。
* 其余任务类型（分割、姿态、旋转框）的推荐值沿用检测的结论，没有各自做对比实验。
* 小数据集（几百张）上的轮数、验证集取舍没有实测；`best.pt` 在小验证集上偏乐观的问题没有处理：想要更可靠的挑选，需要更大的验证集。
* 同一批数据、同一个 seed 的结果；逐轮噪声约 ±0.02，没有做多 seed 重复，所以小于 0.01 的差别不要当真。

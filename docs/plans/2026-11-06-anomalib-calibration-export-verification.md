# Anomalib 逐图校准与手动导出验证记录

## 需求与最终行为

- 一张校准图误报、一致性未通过或推理异常后，继续处理余下图片；逐图保留原文件名、两路分数与判定、阈值、分数差、掩码 IoU 和诊断原文。
- 显示成功比较数、逐图通过/未通过数与百分比、正常图误报数与百分比、整图判定不一致数。推理异常计入逐图未通过；误报率以成功完成双路推理的正常图为分母，避免将无法推理的图片当成正常通过。
- 完整导出但校准未通过时，显示独立的「校准未通过」状态。保留检查点、ONNX、部署清单、配置和 JSON 报告；清理本次生成的数据集副本。
- **不自动加入 Anomalib 验证页。** 用户可以下载 ZIP 和报告，自行决定是否通过现有「添加模型」手动导入。ZIP 仍只有根目录的 `model.onnx` 与 `model.manifest.json`。
- 自动注册规则保持不变：完成全部校准图片、标签一致、最大分数差不超过 0.02、最小掩码 IoU 不低于 0.95，且正常图误报率不超过 5%。手动导入仍执行文件结构、摘要、模型契约及运行时检查，不重新评定业务准确率。
- 真实训练、导出、进程失败仍失败并清理不完整产物；没有把进程异常伪装成校准警告。

## 实现边界

| 层次 | 变化 |
|---|---|
| Python 流水线 | 返回完整逐图报告；非有限分数按单图错误记录；完整生成 ONNX 与清单后设置 `exportSucceeded`，校准质量未通过不再丢弃导出 |
| Tasks 训练服务 | 区分校准未通过与进程失败；仅前者保留完整产物；工作流不覆盖该状态 |
| Server 模型管理 | 按所有者、工程和固定格式运行标识定位训练导出；校验清单、摘要并拒绝链接路径；流式生成磁盘 ZIP，响应关闭后清理临时包 |
| Tasks 页面 | 复用训练卡片样式；详情每页 50 条并在卡片内滚动；中文/英文资源对齐；独立模型包及报告下载 |
| HTTP 下载 | 必须登录，只读取当前用户目录；缺失返回 404；响应为 private/no-store；下载不产生注册标记 |
| 模型导入 | ONNX 上限由 500 MiB 调至 1 GiB，包上限由 512 MiB 调至 1028 MiB；同步 Tasks 提示、API 请求/表单限制和双语 README |

提高导入限额是为了让较大 PatchCore 导出能够通过现有手动导入流程：84960×1536 个 float32 特征约 498 MiB，另有骨干权重及图结构，可能超过旧的 500 MiB 限制。这是容量估算，未用实际 1 GiB 业务模型进行压力测试。

## 使用与未覆盖范围

更新部署后需要重新发起训练；旧版本已经删除的失败产物无法恢复。本次没有修改生产服务器或重启训练服务。

产物保存在磁盘，训练页的最近状态仍保存在应用内存；应用重启后不会自动恢复报告卡片。没有增加历史训练列表或自动恢复功能。

本次没有在 RTX 3060 上完整重训这 81 张业务图片，也没有验证多 GPU、真实大特征库的显存/耗时或业务漏检率。此次修改允许保留结果并人工验证，不保证解决既有误报。此前观察到的训练/导出/推理预处理插值差异不属于本次改动，也尚未证实为业务误报的根因。

浏览器检查使用实际 Razor 渲染结果与产品样式；不等同于浏览器连接真实 GPU 训练任务的端到端验收。最终提交信息以本次交付说明为准。

# Anomalib 正常阈值与大模型导入验证记录

## 问题与证据

用户确认服务器的 81 张正常图中，烟丝覆盖率、网带露底和反光变化全部允许。图片均为 5120×5120 BMP；本次保留的 PatchCore 使用 960 输入、59 张特征训练图、14 张内部验证源图片及另外留出的 8 张最终校准图。

| 项目 | 实际发现 |
|---|---|
| 上传失败 | ONNX 为 1,143,454,730 字节，约 1090.5 MiB，已超过旧的 1 GiB ONNX / 1028 MiB ZIP 限制；不是空包或图片损坏 |
| 原始校准 | 8/8 正常图误报；PyTorch/ONNX 最大分数差约 0.000004，最低掩码 IoU 约 0.999987 |
| 缩放对照 | 用训练的浮点抗锯齿预处理代替 PIL 缩图后，8 张仍误报，排除“只要换缩放就能解决”的判断 |
| 阈值来源 | 原合成异常标定的整图原始阈值约 45.804，14 张内部正常源图的原始分数约为 45.644–58.099，其中 13 张超过原阈值 |
| 模型状态 | 读取成功训练的可信检查点，恢复同一特征库和骨干权重；没有重新抽取 coreset 来掩盖差异 |

本次问题包含两个独立环节：软件的上传限额不足，以及合成异常产生的阈值不适合这批允许较大正常变化的图片。不能把“正常图全部被判异常”直接归因为照片损坏或样本张数不足。

## 修复

1. ONNX 上限调整为 2 GiB、ZIP 上限为 2052 MiB。页面文件流、Server 解包与拷贝限制、API 请求/表单限制以及中英文提示保持一致。超大包显示实际 MiB 和限制；保留大小、两文件结构、算法类型、SHA-256、ONNX 输入输出契约检查。Python 导出计算摘要时改为 1 MiB 分块读取，避免额外分配整个 GB 级模型的内存。
2. 使用内部验证集保留的**原始正常源图片**标定整图分数和每图最大像素分数，采用上侧 95% 经验分位数。59 张特征学习图片与最终 8 张校准图片均不参与这一步拟合。14 个样本时，该分位数取到样本最大值；它不构成总体误报率的统计保证。
3. EfficientAD 仍先恢复最佳检查点，再标定；只同步检查点的后处理状态，不更改最佳轮次和训练权重。标定错误逐图保留并继续处理；出现错误或元数据不完整时禁止自动注册，完整导出仍可手动检查。
4. 新清单声明 `bilinearAntialias`，Python 与 C# 使用 RGB float32 抗锯齿双线性缩放。C# 采用可分离滤波与少量扫描线缓存，不为整张 5K 原图创建浮点副本；普通 32 位像素直接读取，保护原生位图生命周期并使用长整数行偏移。
5. 系数和坐标采用 float32 精度，参考 [PyTorch 上采样内核的计算约定](https://github.com/pytorch/pytorch/blob/v2.7.1/aten/src/ATen/native/cpu/UpSampleKernel.cpp)。大图逐元素对照发现 double 坐标会产生可测偏差，修正后与本地 PyTorch 2.7.1 参考输入的平均绝对差约 2.38e-8、最大差约 3.58e-7；另与生产环境 PyTorch 2.11.0 / torchvision 0.26.0 的完整 2,764,800 个输入值对照，平均绝对差约 2.39e-8、最大差约 3.58e-7，均通过绝对误差 2e-6 检查。
6. 旧清单省略插值字段时保留原双线性行为。旧 ONNX 固化的阈值不会因替换应用代码而自动改变，需要使用重新标定的包或重新训练。

报告新增标定数量、经验分位数、原始阈值前后变化及原始分数明细；归一化后通常仍以 0.5 判定，不能把它当作概率或认为“阈值没有生效”。区域阈值 0.8 的现有默认设置保持不变，仍是额外过滤参数。

## 尚未达到的验收条件

**不能因正常图误报回归通过，就判定真实缺陷检出率合格。** 当前尚未确认一组同机位真实异常图作为验收集。

另用其他场景的羽毛标注图提取前景，贴入正常烟丝图做半合成压力测试，未用这些图片调阈值。贴片宽度在原图中分别为 256、512、1024 像素：前两种整图未判异常；1024 像素贴片整图判异常，模型 0.5 掩码约 1281 个像素，但额外采用区域阈值 0.8 时没有区域通过。贴片宽度不等于实际羽毛轮廓宽度，这组实验也不是实际召回率。

因此，小异物检出仍需同一相机的真实正常/异常图片按业务最小缺陷尺寸验收；不能只提高阈值来宣布完成检测，也不能拿黑背景羽毛图片整图当作烟丝场景的真实异常。当前未增加分块训练/推理，不宣称已解决高分辨率小目标问题。

真实检查点诊断使用 RTX 3060/PyTorch；ONNX 校准与页面端到端验证使用 CPU。未进行 ONNX CUDA、多 GPU训练、实际视频流吞吐或极限 2 GiB 正常模型的压力验收。

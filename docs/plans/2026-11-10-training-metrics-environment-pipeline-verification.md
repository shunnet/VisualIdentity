# 训练指标、环境自检与重置、Anomalib 流水线 v2 的真实环境验证

日期：2026-11-10。验证环境：Linux 服务器，NVIDIA GeForce RTX 4080 16 GB，Python 3.14，PyTorch 2.11 + CUDA 12.8，Anomalib 2.6.2，ONNX Runtime 1.31.1；本机 Windows 用于界面冒烟。

## 要解决的问题

1. Anomalib 的 EfficientAD、PatchCore 训练完成后，门禁仍然无法让全部正常图通过，且显存经常溢出。
2. 设置页选择 GPU 后，SAM、YOLO 训练、Anomalib 训练仍默认 CPU / 自动；缺少环境自检与重置手段。
3. 训练指标没有留档与展示，Anomalib 训练页缺少实时指标；项目卡片没有训练指标入口。

## 根因与修复

| 现象 | 根因 | 修复 |
|---|---|---|
| GPU 训练完成后导出 ONNX 崩溃 | 旧导出路径在 CUDA 上追踪，`clamp` 的 CPU 常量与 CUDA 张量设备不一致（已用旧流水线在服务器复现） | 模型移到 CPU 后导出并做一致性校验 |
| 零误报门禁频繁失败 | 阈值取内部留出正常图的 95% 分位数，按构造约 5% 的新正常图会越线 | 阈值取「留出图最高分 × 1.05」与「均值 + 3.5σ」的较大者，报告写明规则与统计量 |
| PatchCore 显存溢出 | 嵌入矩阵约 patch 数 × 1536 × 4 字节，聚类时峰值约两倍；800 px 不抽样实测峰值 12.8 GB，1024 px 按两倍估算约 27 GB | 训练前按可用显存规划 patch 抽样比例与记忆库大小，显存不足时抽样比例减半重试 |
| EfficientAD 训练慢 | 每轮重复解码 5120 × 5120 级大图 | 训练前一次性缩小为训练尺寸的无损 PNG 工作副本（约快 5 倍）；标定与门禁仍读原图 |
| 磁盘被占满 | 运行目录在成功后仍残留数据集与中间文件 | 成功后只保留模型、清单、报告、检查点与指标 |
| 设置页 GPU 与各处默认值不同步 | 各页面各自默认「自动」 | `DeviceDefaults` 统一换算 SAM、YOLO、Anomalib 的默认设备 |

## 真实图片实验（150 张正常图、121 张已知异常图，只用于评估）

| 模型与设置 | AUROC | 耗时 | 峰值显存 |
|---|---|---|---|
| PatchCore 640 px，1% coreset | 0.983 | 约 31 秒 | 8.2 GB |
| PatchCore 512 px | 0.973 | 约 13 秒 | 5.3 GB |
| PatchCore 800 px，不抽样 | 0.972 | 约 79 秒 | 12.8 GB |
| PatchCore 800 px，抽样 25% | 0.973 | 约 19 秒 | 3.3 GB |
| PatchCore 512 px，10% coreset | 0.964 | 约 2 分钟 | 5.3 GB |
| EfficientAD Small 512 px，120 轮 | 约 0.93（80 轮后 0.91–0.94 波动） | 32 分钟 | 1.3 GB |

- 9 组 PatchCore 设置全部通过零误报门禁。
- EfficientAD 验证 AUROC（合成异常）与真实 AUROC 在平台期（30 轮后）的相关系数约 −0.2，只能用于判断训练是否停滞。
- EfficientAD 的正常图得分呈长尾（中位数约 0.16，最高约 1.44）。按真实得分重采样 20000 次，模拟「27 张留出图标定 + 15 张新图零误报验证」：旧规则门禁失败约 74.6%，新规则约 36.0%；独立同分布下新图出现比全部留出图更高分的概率本就约 15 / 42，加大余量只会降低检出率。因此训练页对 EfficientAD 门禁失败给出改用 PatchCore 的提示。

| 环境自检（YOLO，从未训练过 YOLO 的服务器） | 正确报告虚拟环境未安装并标为「需要修复」 |
| 环境自检（SAM） | 缺少 CUDA 13 / cuDNN 9 运行库时只显示「缺什么」一句话；运行库就位后通过 |

## 环境重置（真实执行）

在服务器的隔离目录里执行（使用独立的 `train/anomalib/.env`，不触碰生产环境）：先从「没有环境」重建，再对已有环境重置第二次。

| 步骤 | 结果 |
|---|---|
| 第一次重置（无旧环境） | 约 9 分钟：创建独立虚拟环境 → 安装 Anomalib 专用 PyTorch（cu128，约 7.5 分钟，主要是下载）→ 安装固定版本 Anomalib 2.6.2 与 ONNX 工具（约 1 分钟）→ 完成 |
| 自检 | 虚拟环境、PyTorch 2.11.0+cu128、`torch.cuda.is_available()`、GPU 上的真实张量运算、设备名、Anomalib 2.6.2、ONNX Runtime 1.31.1 全部通过 |
| 用新环境训练 | PatchCore 512 px 约 57 秒完成并注册，门禁 15 / 15、正常图误报 0 |
| 第二次重置（已有环境） | 删除上一次创建的环境并重建，约 8 分钟；虚拟环境的创建时间随之更新，自检再次全部通过 |


## 界面冒烟（本机，隔离的演示实例）

- 训练指标页：汇总、最佳模型、逐次记录、展开详情与曲线、`.pt` 下载（200，附件名与 `Cache-Control: private, no-store` 正确）、越权路径与未知格式（400 / 404）；YOLO ONNX 导出在训练环境缺失时给出明确提示。
- 设置页：环境管理卡片的自检结果与重置按钮；设置为 GPU 后，YOLO 与 Anomalib 训练弹窗默认选中该 GPU。
- 标注页：先选左侧标签，再点击右侧区域列表中另一标签的标注，左侧选中项同步。
- **冒烟发现并修复的缺陷**：`EnvironmentDiagnosticsService` 与 `SamEnvironmentResetService` 未在 `Program.cs` 注册，设置页一打开就因依赖注入失败而转圈。单元测试没有覆盖，已补注册并新增 `ComponentServiceRegistrationTests`，它扫描全部组件的 `[Inject]` 依赖并在真实宿主容器里逐个解析（取消注册后确认会报红）。

## 界面反馈修复（本地界面实测）

| 反馈 | 原因与修复 |
|---|---|
| 训练指标页第一张卡片与标题栏的间距是卡片之间的两倍 | 标题栏自带下边距，页面又用 flex 间距排列卡片，两者叠加成 24 px；页内去掉标题栏的下边距，实测标题栏到卡片、卡片到卡片都是 12 px（空状态与有数据状态一致） |
| 训练页「训练指标」卡片里，格子数为奇数时最后一行上方缺一段分隔线（EfficientAD 的 5 / 7 格、PatchCore 的 5 / 7 格都会出现，PaDiM 只有 2 格不受影响） | 分隔线只画在每个格子自己所在的那一列；格子总数为奇数时让最后一格占满整行，整条分隔线连续；`数据概览` 等共用这套样式的格子同样受益 |
| YOLO 训练页「训练指标」底部没有折线图 | 状态里新增按轮次记录的曲线（每个轮次一个点，上限 1000 点），页面在指标下方画 mAP50-95 折线，样式与 Anomalib 的验证 AUROC 折线一致；新增 5 个测试 |
| 训练失败（如显存不足）的记录展开后，一整行红色原文把训练指标表拉得很长、出现横向滚动条 | 表格单元格为避免状态徽标折行而设成不换行，展开行继承了它，整段 CUDA / Python 日志按单行排版。展开行恢复换行，内容宽度跟随表格而不参与列宽计算，运行信息按字符换行并保留原有换行、最高 9rem、超出在框内滚动。在 1600 px 宽度下用一条 681 字的显存不足记录和一条 5 KB 的多行回溯实测：表格宽度等于容器宽度，没有横向滚动条；对同一批记录撤掉修复做对照，表格被撑到 28 572 px |
| 显存不足这类在校准之前就失败的运行，详情里显示「校准门禁：校准未通过」「最大分数差 1」 | Python 在流水线异常时写出的失败报告用 1.0 占位分数差且没有任何样本，记录构建器原样存了下来，界面又把「门禁没执行」当成「未通过」。构建器只在真正比较过样本时才记录分数差；记录新增只读属性 `GateEvaluated`（成功导出，或有校准图参与比较），详情对没执行门禁的运行显示「未进入校准」，分数差与掩码 IoU 显示「—」；已经保存的旧记录无需迁移，同样按这条规则显示 |

## 独立代码评审

一名独立评审（只读）审阅了新增的训练记录、导出、环境自检与流水线代码：没有严重问题；中等及以上意见逐条核实后全部修复。

| 意见 | 修复 |
|---|---|
| 训练刚结束时指标页可能读到尚未写入新记录的列表，之后不再刷新 | 页面改为等训练任务（含结束后清理与写记录的收尾）真正结束再刷新 |
| 运行目录创建之前就失败或被取消的训练（例如去重后图片不足 10 张）没有记录 | 补写记录；新增 2 个回归测试，并在服务器上用重复图片验证 |
| 记录文件被篡改（`runs/`、嵌套目录、非 `.pt` 权重）可能让删除越界或导出任意文件 | 删除与下载只接受 `runs` 之下的训练目录和 `.pt`、工程目录的直接子目录 `anomalib-run-*`；新增 4 个测试 |
| ONNX 导出被中断留下残缺文件，之后被当作成功结果复用；并发请求重复导出 | 按权重串行化导出、写入完成标记、失败时清理、复用前核对大小；新增 3 个测试 |
| CPU 训练被记成 GPU 训练，还按 GPU 显存抽样 patch | 只有 GPU 训练才记录显卡与显存，CPU 训练不按显存规划；服务器上用 CPU 实测 |
| 显存不足重试在 `except` 块内释放显存（块内回溯仍引用模型）；多卡时每个进程都输出实时曲线 | 释放移到块外，重试读到的可用显存才准确；只由主进程输出；新增 2 个 pytest |
| 保存记录抛出意外异常会让 YOLO 一直显示忙碌；新增了一处 `lock` | 收尾保存不再向外抛异常，改用已有的状态副本接口 |
| YOLO 最佳轮次的 fitness 与 Ultralytics 不一致；训练集上算的指标压过有验证集的结果；准确率被标成 mAP50-95 | fitness 按 Ultralytics 定义（分割加掩码、姿态加关键点、分类取 top1 与 top5 均值）；最佳模型优先选用了验证集的训练；标签改为「准确率」 |
| 设置页：SAM 重置日志对所有用户可见；轮询永不停止；自检可并发拉起多个 PyTorch 进程；纯 CPU 的 SAM 发行包一直提示需要修复；重置先删后装 | 日志只给管理员；没有重置时停止轮询；同一组件自检排队执行；GPU 项只看「要求项」；旧运行库先移到备份，安装成功后才删除，失败或取消时恢复 |

记录在案、未处理：设置页的「仅管理员」检查在界面层（与既有的、工程所有者即可使用的训练页重置按钮一致）；环境自检会在 GPU 0 上创建一个小的 CUDA 上下文，训练中显存极度紧张时可能失败。
